## 概述

**已验证的现状**（读自 `src-tauri/src/`，尚未上升为规则）：

- 每个 `#[tauri::command]` 都返回 `Result<T, String>`。crate 里**没有**自定义错误枚举，也**没有** `thiserror` / `anyhow` 依赖。
- 错误用 `.map_err(|error| format!("…：{error}"))` 产生——一段简短的人话前缀，拼上底层错误。
- 错误信息是**简体中文**，拼接原因前用**全角冒号** `：`。实例：`"所选文件不存在"`、`format!("读取文件失败：{error}")`、`format!("保存文件失败：{error}")`。
- 卫语句（guard clause）提前返回（`if !file_path.is_file() { return Err(...) }`），不做嵌套。
- 前端收到的是纯字符串，所以错误的**种类**目前不可机读——需要分支判断的调用方只能做字符串匹配。

需要团队拍板的问题：

1. 继续用 `Result<T, String>`，还是引入一个能序列化成结构化载荷（kind + message）的类型化错误枚举？
2. 「错误信息用中文」是全项目规则，还是只针对要上屏的字符串？（`src` 里字面中文和 `\uXXXX` 转义中文是混用的。）
3. 信息里是否总要点名被操作的资源，还是现在这种极简写法就够？
