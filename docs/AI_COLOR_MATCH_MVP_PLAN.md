# AI 追色 Windows 客户端 MVP 开发计划

> 项目代号：色迹（ChromaTrace）  
> 文档版本：v1.3  
> 更新日期：2026-07-19  
> 目标平台：Windows 10/11 x64  
> 第一版目标：以较低技术复杂度交付一个可安装的 Windows AI 追色客户端，默认支持本地追色，并可选接入 OpenAI 或 OpenAI 兼容视觉模型。

---

## 1. 项目目标

第一版只解决一个核心问题：

> 用户在 Windows 客户端中选择一张原片和一张参考图，系统在本地分析两张图片的亮度与色彩特征，将参考图的整体色彩风格迁移到原片，并允许用户调整匹配强度后导出效果图。

第一版重点不是训练复杂的生成式模型，而是使用成熟、可控的颜色统计与图像处理算法验证追色体验。该功能在产品界面中统一称为“AI 追色”，内部实现采用可解释的智能分析算法。

### 1.1 核心价值

- Windows 原生交付：提供可安装的 `.exe` 客户端。
- 本地优先：默认追色不上传图片，断网也能使用；用户可主动启用视觉模型增强模式。
- 操作简单：选择原片、选择参考图、点击追色即可得到结果。
- 结果可控：提供匹配强度、明度保护、肤色保护和基础微调。
- 快速响应：使用缩略预览和 Canvas 完成第一版实时处理。
- 模型可配置：支持 Base URL、API Key、模型名称和接口类型配置。
- 可持续升级：后续可以将 TypeScript 颜色引擎替换为 Rust 或 ONNX 模型。

## 2. 第一版功能范围

### 2.1 必须实现

1. **Windows 客户端外壳**
   - 使用 Tauri 2 打包。
   - 提供 Windows x64 安装程序。
   - 应用可离线启动和运行。
   - 应用窗口支持最小化、最大化、关闭和尺寸调整。
   - 首次安装时处理 WebView2 运行环境依赖。

2. **原片导入**
   - 支持 Windows 原生文件选择对话框。
   - 支持拖拽 JPG、JPEG、PNG、WebP 文件到窗口。
   - 显示文件名、分辨率和缩略图。
   - 支持替换和删除当前原片。

3. **参考图导入**
   - 支持 Windows 原生文件选择对话框和拖拽。
   - 显示参考图缩略图。
   - 自动提取参考图颜色特征。

4. **图片分析**
   - 分析 RGB 通道均值和标准差。
   - 分析整体亮度和饱和度。
   - 生成亮度直方图。
   - 估算冷暖倾向和绿/洋红倾向。

5. **AI 追色**
   - 将原片颜色分布向参考图靠拢。
   - 自动估算曝光、对比度、色温、色调和饱和度建议值。
   - 在本地完成分析和颜色迁移。
   - 支持追色结果实时预览。

6. **人工控制**
   - 匹配强度。
   - 保留原片明度。
   - 肤色保护。
   - 曝光、对比度、色温、色调、饱和度。
   - 一键重置全部参数。

7. **效果对比**
   - Before/After 分割线对比。
   - 支持拖动对比位置。
   - 显示当前渲染状态。

8. **效果图导出**
   - 通过 Windows 原生保存对话框选择文件名和位置。
   - 第一版导出 JPEG。
   - 默认 JPEG 质量不低于 90%。
   - 导出完成后显示成功或失败提示。

9. **模型服务配置**
   - 默认关闭，用户主动启用“视觉模型增强”。
   - 支持配置服务商名称、Base URL、API Key、模型名称和接口类型。
   - 接口类型支持 OpenAI Responses API 和 OpenAI 兼容 Chat Completions。
   - 支持请求超时设置和“测试连接”。
   - API Key 不写入前端源码、配置文件或 `localStorage`。
   - 用户的 API Key 通过 Rust 层保存到 Windows Credential Manager。

10. **视觉模型增强追色**
   - 仅发送缩放后的原片和参考图，不发送原始分辨率文件。
   - 首次启用时明确提示图片会发送给用户配置的服务商。
   - 模型返回结构化调色参数，不直接生成最终图片。
   - 返回参数经过 JSON Schema 校验和安全范围裁剪后，交给本地颜色引擎应用。
   - 模型请求失败、超时或返回无效数据时，自动回退到本地追色。

11. **错误处理**
   - 不支持的文件类型提示。
   - 图片读取或解码失败提示。
   - 未同时载入两张图片时禁止开始追色。
   - 无写入权限或保存失败时给出明确提示。
   - Base URL、API Key 或模型未配置时给出明确提示。
   - 网络超时、鉴权失败、模型不支持图片时显示可理解的错误信息。

### 2.2 第一版暂不实现

为避免 MVP 过度复杂，以下功能延期：

- Lightroom XMP 预设生成和导入。
- CUBE LUT 导入与导出。
- RAW、DNG、HEIC 专业解码。
- 云端账号、同步、分享和软件方统一 API 代理服务。
- 批量追色。
- Rust 高性能图像处理核心。
- PyTorch 自训练模型和 ONNX Runtime 本地推理。
- 局部蒙版、人物分割、天空识别。
- 完整 ICC 色彩管理。
- 自动更新、崩溃上报和在线埋点。
- 软件方 API Key 内置或由软件方统一承担模型费用。
- Windows ARM64、macOS 和 Linux 安装包。

以上功能保留架构扩展点，但不进入第一版验收范围。

## 3. 第一版技术栈

第一版采用“轻量 Tauri 桌面壳 + React 本地图像引擎 + 可选视觉模型接口”，满足 Windows 客户端要求，同时避免过早引入复杂 Rust 图像算法。

| 层级 | 技术 | 用途 |
|---|---|---|
| 桌面客户端 | Tauri 2 | Windows 窗口、原生对话框、安装包和本地权限 |
| UI 框架 | React + TypeScript | 页面、交互和参数状态 |
| 构建工具 | Vite | 前端开发与生产资源构建 |
| 图片处理 | Canvas 2D + ImageData | 图片分析、像素变换和预览 |
| 并发优化 | Web Worker，按实际性能引入 | 避免大图处理阻塞 UI |
| Rust 层 | Tauri Commands + reqwest | 文件读取、保存、密钥管理和模型 API 请求 |
| 样式 | 原生 CSS + Design Tokens | 定制调色工作台界面 |
| 图标 | Lucide React | 功能图标 |
| 前端测试 | Vitest | 颜色算法和工具函数测试 |
| 密钥存储 | Windows Credential Manager | 保存用户自备 API Key |
| 配置存储 | Tauri Store 或本地 JSON | 保存 Base URL、模型等非敏感配置 |
| Windows 打包 | Tauri Bundler + NSIS | 生成 Windows .exe 安装程序 |

### 3.1 第一版架构原则

```text
Windows 用户
    ↓
Tauri 2 应用窗口
    ↓
React 调色工作台
    ├── 本地模式 → Canvas / ImageData 颜色引擎
    └── 增强模式 → Tauri Rust → OpenAI / 兼容视觉模型
                         ↓
                  返回结构化调色参数
                         ↓
                  本地颜色引擎应用参数
    ↓
Tauri 原生文件选择与保存
    ↓
Windows 本地图片文件
```

- Tauri 负责窗口、安装包、原生文件对话框和权限边界。
- React 负责全部 UI 和工作流。
- 第一版颜色分析和追色算法继续使用 TypeScript，以降低实现复杂度。
- Rust 保留必要的 Tauri 工程，并负责原生文件操作、Windows 凭据访问和模型请求。
- 本地追色模式完全在本机完成，不需要后端服务。
- 视觉模型增强模式采用 BYOK：用户自行配置 API Key 和服务地址。
- 软件方不在安装包中内置统一 API Key。

### 3.2 为什么不在第一版引入完整 Rust 图像引擎

MVP 需要优先验证追色效果与用户工作流，而不是追求专业修图软件级性能。Canvas 处理缩放后的预览图足以完成第一阶段验证。

当出现以下任一情况时，再迁移到 Rust：

- 需要导出相机原始分辨率图片；
- 需要批量处理；
- 单张图片处理明显阻塞界面；
- 需要 TIFF、RAW 或完整 ICC 色彩管理；
- 需要与 ONNX Runtime 组合进行本地推理。


- 第一版不做多窗口和系统托盘。

## 5. AI 追色算法方案

### 5.1 算法定位

第一版使用“统计颜色迁移 + 参数估计”，不使用大型神经网络。

要求：

- 可解释；
- 无需模型文件和网络连接；
- 运行速度快；
- 支持连续可调的匹配强度；
- 可以作为后续真实 AI 模型的基线方案。

### 5.2 处理流程

```text
原片、参考图
  ↓
缩放到分析尺寸（最长边 512～900 px）
  ↓
过滤透明像素和无效像素
  ↓
计算亮度、饱和度、通道均值和标准差
  ↓
估算两张图片的颜色分布差异
  ↓
生成颜色迁移结果
  ↓
应用明度保护、肤色保护和匹配强度
  ↓
应用曝光、对比度、色温、色调和饱和度
  ↓
绘制 Before/After 预览
```

### 5.3 基础颜色迁移

对每个颜色通道标准化并重新映射：

```text
matched = (source - sourceMean)
          × referenceStd / sourceStd
          + referenceMean
```

按匹配强度混合：

```text
output = source × (1 - strength)
       + matched × strength
```

通道缩放比例必须限制在安全范围内：

```text
channelScale ∈ [0.45, 2.20]
```

避免低方差图片造成严重偏色或通道溢出。

### 5.4 明度保护

颜色迁移后重新计算像素亮度，并按“保留原片明度”参数，将结果亮度向原像素亮度校正。色彩迁移与整体曝光调整应保持相对独立。

### 5.5 肤色保护

第一版不做人物分割，使用 HSV/HSL 范围生成软肤色 Mask：

- 检测橙红到黄色之间的 Hue；
- 排除饱和度和亮度过低的像素；
- 对可能的肤色像素降低迁移强度；
- 使用连续权重，不使用直接二值化。

该方法可能同时保护木材、沙地和暖色墙面，因此用户必须能够将肤色保护调为 0。

### 5.6 自动参数估计

```text
曝光：log2(referenceLuma / sourceLuma)
对比度：referenceStd / sourceStd
色温：参考图红蓝差 - 原片红蓝差
色调：参考图洋红绿差 - 原片洋红绿差
饱和度：referenceSaturation - sourceSaturation
```

建议安全范围：

```text
曝光       [-2, 2]
对比度     [-45, 45]
色温       [-55, 55]
色调       [-45, 45]
饱和度     [-35, 35]
```

## 6. 模型服务配置与调用方案

### 6.1 配置字段

```ts
interface ModelConfig {
  enabled: boolean
  providerName: string
  baseUrl: string
  apiKeyStored: boolean
  model: string
  apiType: 'responses' | 'chat-completions'
  timeoutSeconds: number
  maxImageSide: number
}
```

设置页面至少提供：

- 启用视觉模型增强；
- 服务商名称；
- Base URL；
- API Key；
- 模型名称；
- API 类型；
- 请求超时，默认建议 60 秒；
- 测试连接；
- 清除凭据；
- 恢复默认配置。

OpenAI 官方服务的预置 Base URL 为：

```text
https://api.openai.com/v1
```

模型名称不硬编码为长期固定值，由用户填写或从兼容服务提供的模型列表中选择。第一版不要求所有兼容服务都实现模型列表接口。

### 6.2 密钥安全

- 软件方 API Key 禁止硬编码到 React、Rust、环境文件或安装包。
- 用户输入的 API Key 只传递到 Tauri Rust 层。
- Rust 层通过 Windows Credential Manager 保存、读取和删除凭据。
- React 状态仅保留“已配置”状态，不回显完整 API Key。
- Base URL、模型、接口类型等非敏感配置可以保存到 Tauri Store。
- 日志、Toast 和错误报告不得包含 API Key 或完整认证请求头。

第一版采用用户自备密钥（BYOK）方案。如果后续由软件方统一提供模型额度，必须增加后端代理，不能把统一密钥放在客户端。

### 6.3 请求数据与隐私

视觉模型模式需要将图片发送到用户配置的模型服务，因此必须：

1. 默认关闭视觉模型增强。
2. 首次启用时显示隐私确认。
3. 明确展示目标服务的 Base URL。
4. 只发送缩小后的图片，默认最长边不超过 1024 px。
5. 移除不必要的 EXIF 元数据。
6. 不发送本地文件路径。
7. 请求结束后不在应用内持久化请求图片副本。

本地模式始终可用，并继续显示“图片仅在本机处理”。视觉模型模式启用后，该提示必须改为“缩略图将发送至已配置的模型服务”。

### 6.4 模型输入和输出

模型输入：

```text
原片缩略图
参考图缩略图
固定的追色分析提示词
严格的结构化输出约束
```

模型只负责分析，不直接生成图片。建议返回：

```json
{
  "exposure": 0.25,
  "contrast": 12,
  "temperature": 18,
  "tint": -4,
  "saturation": -8,
  "matchStrength": 82,
  "preserveLuma": 70,
  "skinProtect": 65,
  "styleDescription": "暖色、低对比、轻微褪色"
}
```

客户端收到结果后执行：

```text
解析 JSON
  ↓
检查必填字段和数值类型
  ↓
按安全范围裁剪
  ↓
与本地统计追色结果融合
  ↓
Canvas 引擎应用参数
  ↓
显示 Before/After
```

### 6.5 接口兼容

第一版支持两种接口类型：

1. **OpenAI Responses API**
   - 用于 OpenAI 官方接口。
   - 支持图片输入和结构化参数返回。

2. **OpenAI 兼容 Chat Completions**
   - 用于实现兼容接口的第三方或自建服务。
   - 不假设所有服务支持 Responses API。
   - 不假设所有模型支持视觉输入。

Base URL 拼接必须集中在 Rust API 客户端模块中，避免 UI 组件自行拼接 `/responses` 或 `/chat/completions`。

### 6.6 降级策略

以下情况自动回退到本地追色，并保留可理解的错误提示：

- 未配置 API Key；
- 无网络连接；
- Base URL 无法访问；
- 401/403 鉴权失败；
- 429 限流；
- 请求超时；
- 模型不支持图片输入；
- 返回内容不是有效 JSON；
- 参数超出允许范围；
- 兼容服务返回未知格式。

模型增强失败不得阻止用户继续调整和导出本地追色结果。

## 7. 性能与本地文件策略

### 7.1 分辨率分级

| 用途 | 建议尺寸 |
|---|---|
| 色彩特征分析 | 最长边 512～700 px |
| 实时预览 | 最长边 900～1200 px |
| 第一版导出 | 最长边 1600～2400 px，按设备性能限制 |

不得在每次拖动滑块时直接处理相机原始尺寸图片。

### 7.2 渲染节流

- 滑块变化后延迟约 30～60ms 处理。
- 新任务开始时取消尚未执行的旧任务。
- 图像分析结果缓存，不重复计算。
- 如果主线程出现明显卡顿，将颜色处理移到 Web Worker。

### 7.3 文件与内存管理

- 文件选择使用 Tauri Dialog 插件。
- 文件保存位置由用户在原生保存对话框中决定。
- Tauri 权限仅开放应用实际需要的读取和保存能力。
- 更换图片后释放 Object URL。
- 不长期保存多个完整 `ImageData` 副本。
- 超大图片先缩放，再读取像素。
- 第一版不建立图片云端副本或缓存服务。

颜色算法模块不得依赖 React 或 Tauri，使其可以独立测试，并在后续迁移到 Web Worker、WASM 或 Rust 时保持接口稳定。

## 12. 已知限制

1. “AI 追色”是整体颜色分布迁移，不能理解摄影师的全部局部调整意图。
2. 参考图与原片的光照和主体差异越大，结果越不稳定。
3. 简单肤色检测可能同时保护木材、沙地等暖色物体。
4. 第一版 Canvas 引擎不提供专业级完整 ICC 色彩管理。
5. 第一版不处理 RAW，不保证与 Lightroom 完全一致。
6. 第一版导出效果图，不生成 Lightroom 预设。
7. 视觉模型增强依赖用户配置的服务可用性、网络、额度和模型视觉能力。
8. 不同 OpenAI 兼容服务的请求和返回格式可能存在差异，第一版不能保证全部兼容。
9. 第一版只正式支持 Windows x64。
10. 第一版导出分辨率会受到设备内存和 Canvas 能力限制。

## 14. 当前实施决定

1. 第一版必须交付 Windows 客户端，而不是普通网页。
2. 第一版使用 Tauri 2 + React + TypeScript + Vite。
3. Tauri 负责安装包、窗口、文件对话框、本地权限、凭据和模型请求。
4. 第一版保留 Canvas 2D + TypeScript 本地追色，并作为默认和失败降级方案。
5. 第一版加入可选视觉模型增强，支持 Base URL、API Key、模型和接口类型配置。
6. 模型模式采用用户自备密钥（BYOK），API Key 存入 Windows Credential Manager。
7. 模型只返回结构化调色参数，最终预览和导出仍由本地颜色引擎完成。
8. 本地模式不上传图片；模型模式只在用户确认后发送缩略图到所配置的服务。
9. 第一版只实现 AI 追色和 JPEG 导出，不实现 Lightroom 预设与 CUBE。
10. 颜色算法保持独立，后续可以迁移到 Web Worker、Rust 或 ONNX。
11. 第一版发布目标为 Windows 10/11 x64 NSIS `.exe` 安装程序。

该范围冻结后，如无影响 Windows 交付或核心追色流程的问题，不在 MVP 中增加新的文件格式、云端服务或专业调色模块。
